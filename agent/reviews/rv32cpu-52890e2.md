## Findings

1. HIGH - `tb/run_mmio.sv:60` (`#UBYTE` display for every UART byte, enabled by `dbg_on = 1` at line 52) corrupts the m7 pass check: every UART char is glued to a debug line, so no log ever contains the contiguous string PASS; `Makefile:212` `grep -q PASS` fails for all 5 programs, so `hdl make m7 CACHE_LAT=1` prints `M7 TEST FAILED: 5 errors`. The PROMPT requires m7 to keep passing after each step; the parent commit did pass. The CPU and the C programs are fine (runs complete and HALT=1 with expected UART_BYTES); this is self-inflicted test-suite breakage by the debug line. Fix by gating the debug with an ifdef or by checking the #UBYTE hex byte markers instead of literal text.
2. MEDIUM - no committed recipe for the claimed probe runner: `build/vlt_big/run_mmio_big` has no Makefile rule, and `build/doom/fsys.o` has none either (its compile even needs an undocumented `--specs=picolibc.specs` to find stdio.h). The metrics reproduce, but only because I had to reconstruct build flags; pin them in the Makefile for a fresh clone.
3. MEDIUM - FPGA build still contains feature stubs `rtl/csrs.sv:74-76`: `mc_ref/min_ref/minh_ref = 32-h0` under ifdef FPGA, so mcycle/minstret read as 0 in the FPGA build. Pre-existing (F4 p1), not introduced here, but still open per the F4 DONE CHECKLIST and must not be papered over by a later MET marker. FPGA mul is schoolbook (~33 cycles) via `rtl/mdiu_fpga.sv`, also still open for the DSP checklist item.
4. LOW - MI subset honesty: `Makefile:31` MI_NAMES has 14 of the 16 official rv32mi tests. `pmpaddr` legitimately needs PMP (not implemented). `sh-misaligned` however passes today on this CPU: I built and ran it (`build/mi/sh-misaligned.hex` + run_hex lat1: `TEST PASSED (39 instrs)`, ISS `--pass` exit 0).
