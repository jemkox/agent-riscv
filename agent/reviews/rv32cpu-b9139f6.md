## Findings

1. [medium] Hard-coded /home path - `Makefile:219` - `build/doom/wad.bin` copies `/home/USER/agent-workspace/downloads/doomwad/doom1.wad` verbatim; introduced in this very commit. Breaks the "no /home paths" rule (riscv-tests dir is parameterized via `RVTEST_DIR`; the WAD is not). Any clone/user outside this exact tree cannot build the doom probe.
2. [medium] F4 claim: standalone FPGA-MDU testbench does not exist - F4 p1 claims "FPGA MDU standalone `1819` cells (`1173 SB_LUT4 + 314 SB_CARRY + 332` DFF)" and "45/45 TEST PASSED", with a run command referencing `build/mdiu_tb.sv`. `git ls-files` shows no such file anywhere (`tb/` has only fpga_tb, main_doom.cpp, run_doom, run_hex, run_mmio). The FPGA-only `rtl/mdiu_fpga.sv` (33-cycle schoolbook MUL/DIV) is consequently never tested: the FPGA ROM program `tests/t01_basic.S` contains no mul/div, and simulations use `mdiu_fast`. The FPGA binary multiply path is unverified.
3. [medium] UM aggregate metric wrong/stale - PROGRESS F4 p1 metrics line claims `INSN=1919 CYCLES=2874 IPC=0.668`; my rerun of `hdl make um` gives `INSN=1917 CYCLES=3079 IPC=0.623` (consistent with their own per-test numbers 507+505+505+505+264+265+264+264=3079, and with the F1+F2 section 0.623). The 0.668 figure cannot come from the quoted per-test values.
4. [medium] FPGA CSR counters still constant-stubbed - `rtl/csrs.sv:74-76` - under `ifdef FPGA`, `mc_ref/min_ref/minh_ref = 32'h0` feed CSRRS reads and `mcycle/minstret` outputs (`csrs.sv:102-126, 212-213`). The F4 DONE CHECKLIST explicitly requires "mcycle/minstret restored in the FPGA build (no constant-0 stubs)"; this is the known failure kind "features stubbed to constants". PROGRESS describes it (iteration 1 "CSR counter stub") but the checklist item remains open.
5. [low] F4 checklist item "2 critical-path design changes" not met - iteration table: (1) regs32 to SB_RAM40_4K (structural, bundled with the counter stub), (2) reverted, (3) nextpnr seed search. Only one net structural change.
6. [low] `Makefile:252-254` `lat1:` runs `make test` twice - cosmetic copy/paste; harmless.
7. [low] `m7` target validates with `grep -q PASS` (`Makefile:212`) - loose, but each program prints a specific `NAME PASS` only after its self-check (verified in logs); acceptable.
